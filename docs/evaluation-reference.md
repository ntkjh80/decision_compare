# 자유 성능평가 상세 안내

[평가 페이지](http://127.0.0.1:8765/evaluation)에서 질문, 선택지, 정답 데이터와 실행 설정을 바꿀 수 있습니다. 기존의 기밀 문서 검토와 별도 화면입니다. 세 유형은 각각 독립적인 편집 내용을 메모리에 유지합니다. 다른 유형으로 갔다 돌아와도 입력이 유지되지만 **새로고침·앱 종료 시 사라집니다**.

1. **Choice**: `billing = 결제 문의`처럼 선택지 ID와 의미를 작성합니다. 2~10개를 지원합니다. 정답은 ID입니다.
2. **Score**: 낮은 수준부터 단계 설명을 한 줄에 하나씩 씁니다. 2~10단계, 첫 단계는 0입니다. 출력은 `Σ 단계 × 확률`인 기대값이라 소수일 수 있습니다. 정답도 범위 안의 숫자입니다.
3. **Noul**: 명제와 true/false의 의미를 작성합니다. 모델은 명제가 참일 확률을 반환합니다. 기본 판정은 `p(true) ≥ 0.5`이며, 결과의 기준을 바꾸면 재추론 없이 다시 집계합니다.

각 유형에 가상의 한국어 예제 6건이 있습니다. 자유 입력은 1~100건, 총 측정 요청은 최대 1,000건입니다. 업로드는 UTF-8 JSON 배열이며 `name`, `text`, `expected`를 사용합니다. 정답 미지정은 `null`입니다. 원문·질문·선택지의 한 요청 합계는 UTF-8 24KB까지입니다. 길이 제한은 모델 자체의 토큰 한도를 보장하지 않으며, 전용 실행기가 잘림을 알리면 채점에서 제외합니다. Ollama 입력 토큰 수가 설정 공간에 근접한 응답도 보수적으로 제외합니다. 호환 서버의 입력 한도·잘림 정책은 서버 설정도 확인하세요.

**모델 연결:** 설치된 모델 찾기는 Ollama와 Ollaya의 모든 로컬 모델을 가져옵니다. 임의의 로컬 모델과 llama.cpp 주소도 직접 추가할 수 있습니다. Ollaya는 전용 `/api/decide`를 사용합니다. Ollama·llama.cpp는 답 토큰 확률 또는 JSON 확률 생성을 선택할 수 있습니다. JSON의 확률은 모델이 자체 생성한 값입니다. 토큰 방식은 A~J의 필요한 확률이 모두 있어야 하며 누락을 0으로 대체하지 않습니다. 이 앱은 클라우드 Jev에 연결하지 않습니다. **JevK5는 TypeSafe Jev와 다른 모델**입니다.

**실행 설정:** 반복 1~10회, 모델별 준비 요청 0~1회, 입력 순서 또는 고정 시드 순서, 제한 시간, Ollama 입력 공간, 토큰 보정 온도를 지원합니다. 준비 요청은 첫 번째 평가 문서를 사용하며 지표에서 제외하고 기록은 별도로 남깁니다. 모델별로 모든 입력을 순차 처리합니다. 반복 시 캐시가 영향을 줄 수 있습니다. 모델 실행 순서는 선택 모델 순서로 고정되어 있으며 무작위 순서는 문서에만 적용합니다.

### 지표의 정확한 정의

**화면에서 바로 설명 보기:** 결과표의 지표 이름 옆 **ⓘ**를 누르면 현재 결과 위에 설명 창이 열립니다. 그래프 옆 ‘설명’, 결과 설정 아래 도움말, 클래스별 표의 Precision·Recall·F1·혼동행렬 도움말도 같은 방식입니다. 닫기 또는 Escape를 누르면 결과로 돌아옵니다. 설명을 읽어도 입력·결과·판정 기준은 바뀌지 않습니다.

페이지 아래 **‘평가 지표, 숫자 예시로 이해하기’**에는 전체 설명이 있습니다. 목차로 이동하거나 필요한 항목만 펼칠 수 있고 ‘모두 펼치기’로 한 번에 읽을 수도 있습니다. 각 설명은 **쉬운 뜻 → 숫자 예시 → 이 앱의 계산 기준 → 해석 시 주의점**으로 구성했습니다. 예시 숫자는 이해를 돕기 위한 가상 값이며 실제 모델 측정 결과가 아닙니다.

| 지표 | 분모·계산 규칙 |
|---|---|
| Accuracy | 정답이 있는 유효 응답 중 맞힌 비율. 정답 미지정·실패 제외 |
| 실패 포함 정답률 | 정답이 있는 모든 실행 요청 중 유효하고 맞힌 비율. 실패를 분모에 포함 |
| Precision / Recall / F1 | 클래스별 혼동행렬에서 계산. Precision·Recall 분모가 없으면 `—` |
| macro-F1 | 설정한 모든 클래스의 F1 평균. 정답·예측 둘 다 없는 클래스는 0 |
| 선택 확률 ECE | 선택한 답의 확률을 5/10/15/20개 동일 폭 구간에 넣고 `Σ (구간 N / 전체 N) × |평균 확률 − 정답률|`. 1은 마지막 구간. 빈 구간 제외 |
| Confidence ECE | 위 식에 검토 기준용 Confidence를 대신 사용. 정답률 보정을 진단할 때 참고하며 선택 확률 ECE와 동일한 의미가 아님 |
| API Confidence | Ollaya Choice·Score: `(K × 최고 확률 − 1) / (K − 1)`. Noul은 이 값이 없어 선택한 판정의 확률 사용. 일반 LLM 어댑터도 API Confidence를 임의 생성하지 않음 |
| 스키마 위반율 | 스키마 검증 가능 응답 중 실패한 비율. HTTP 연결·시간 초과·지원 불가·잘림·완전성 미확인은 분모 제외하고 전체 실패율에 집계 |
| 토큰 방식의 타입 안전성 | 앱이 확률에서 구성한 결과 계약을 검사함. 원시 생성 텍스트의 스키마 위반율을 측정한 값이 아님. 방식이 다른 모델끼리 이 값만으로 구조적 안전성을 주장하지 말 것 |
| p50 / p95 | **브라우저 요청 시작부터 JSON 응답 완료까지** 초 단위. 실패도 포함, 준비 요청 제외. 정렬 후 `(N−1)×q` 위치를 선형 보간. 모델 준비·추론 시간은 별도 |
| 인간 검토율 | 유효 응답 중 설정한 확신도보다 낮은 비율. 기본은 API Confidence, 없으면 선택한 답의 확률. 확신도의 출처는 문서별 카드에 표시 |
| 전체 검토 필요율 | 낮은 확신 + 모든 실패를 전체 측정 요청으로 나눔. 실제 검토 시스템에 전송하지는 않음 |
| 자동 처리 정확도 | 임계값 이상인 성공 응답 중 정답이 있는 건의 정확도. 검토 비율과 함께 확인 |
| ROC / AUC | 정답 양성·음성이 모두 필요. 같은 점수는 한 번에 처리, 사다리꼴 적분. Noul은 참/거짓, Choice·Score는 선택한 클래스 대 나머지(OvR) |
| macro-AUC | 모든 설정 클래스에서 양성·음성이 모두 있을 때 클래스별 OvR AUC 평균. 일부가 없으면 `—` |
| AP | 선택 클래스의 Average Precision. 재현율 증가분에 해당 지점 정밀도를 곱해 합산. 단순 PR 곡선의 사다리꼴 면적과 다름 |
| Brier | Noul은 `(p(true)−정답)^2` 평균(0~1), 다중 클래스는 모든 클래스 확률 제곱 오차의 합 평균(0~2). 서로 다른 유형의 수치는 직접 비교하지 말 것 |
| Score MAE / RMSE | 기대 점수와 숫자 정답의 오차 / 제곱 오차 제곱근. 소수 정답도 포함. 분류 지표는 정수 정답만 사용하며 예측은 최고 확률 단계 |

신뢰도 곡선, ROC, Coverage–Risk, p50·p95 막대, 클래스별 표, 혼동행렬, ECE 구간별 수, 임계값별 ROC 수치, 오류 목록이 제공됩니다. 샘플이 적거나 한 클래스만 있을 때 지표를 0으로 꾸미지 않고 `—`로 표시합니다. ROC에서 보이는 임계값은 데이터에서 관측한 점수입니다. 기준을 최적화한 데이터와 최종 평가 데이터는 분리하세요. 표본 반복은 별도 요청 관측치로 집계하며 표본 독립성이나 통계적 신뢰구간을 주장하지 않습니다.

#### 예시로 구분하는 핵심 지표

환불 문의 100건을 모두 정상 처리했다고 가정합니다. 실제 환불은 20건이고 모델은 그중 16건을 찾고 4건을 놓쳤습니다. 실제 비환불 80건 중에서는 8건을 잘못 잡고 72건을 제대로 제외했습니다.

- **Accuracy 88%:** 전체 100건 중 16+72건을 맞혔습니다.
- **Precision 약 66.7%:** 환불이라고 고른 24건 중 진짜 환불이 16건입니다. 불필요하게 잡은 사례가 얼마나 섞였는지 봅니다.
- **Recall 80%:** 실제 환불 20건 중 16건을 찾았습니다. 찾아야 할 대상을 얼마나 놓쳤는지 봅니다.
- **환불 클래스 F1 약 0.727:** `2×16 ÷ (2×16+8+4)`. Precision과 Recall을 함께 반영합니다. macro-F1은 이처럼 계산한 클래스별 F1의 단순 평균입니다.
- **ROC의 한 점 (0.10, 0.80):** 비환불을 잘못 잡은 비율은 `8/80=10%`, 환불을 찾아낸 비율은 `16/20=80%`입니다. AUC는 이런 점들을 여러 판정 기준에서 모은 곡선의 면적이며 정확도 88%와는 다른 지표입니다.

운영 비율은 별도의 예로 생각해 보세요. 정답을 아는 요청 100건 중 10건이 실패하고, 유효 응답 90건 중 72건을 맞히면 **Accuracy는 80%, 실패 포함 정답률은 72%**입니다. 유효 응답 중 18건의 확신도가 낮다면 **인간 검토율은 20%, 실패 포함 검토 필요율은 28%, 자동 처리 비율은 72%**입니다. 검토율을 낮추는 것만 목표로 삼지 말고 자동 처리된 답의 정확도를 함께 확인하세요.

확률 0.9로 답한 10건 중 8건이 맞으면 그 구간의 보정 오차는 **0.1, 즉 10%포인트**입니다. ECE는 이런 간격을 구간의 표본 비중으로 가중한 평균입니다. 오답률과 같지 않으며, 보정이 잘 맞아도 정확도는 낮을 수 있습니다. API Confidence는 선택 확률과 다른 정의이므로 두 ECE를 구분합니다.

**Score**의 단계 확률이 `[0.1, 0.6, 0.3]`이면 기대 점수는 `0×0.1+1×0.6+2×0.3=1.2`입니다. 가장 유력한 단계인 1점과 다릅니다. MAE·RMSE는 1.2와 정답 숫자를 비교하고, 분류 지표는 최고 확률 단계인 1과 정수 정답을 비교합니다. 소수 정답은 수치 오차에만 포함합니다.

전체 설명의 원본은 저장소 루트 기준 `dist/evaluation.html`의 `metric-guide` 영역입니다. `dist/evaluation.js`의 `openMetricHelp()`가 해당 본문을 설명 창에 재사용하므로 두 화면의 설명을 따로 고칠 필요가 없습니다. 계산식은 기존 `dist/evaluation-metrics.js`를 그대로 사용합니다. 공식 정의 및 API 계약 확인일은 2026-10-11입니다.

### 저장과 재현

- **질문·데이터 저장**: 입력 원문, 정답, 질문, 모델 목록, 실행 조건을 포함한 JSON입니다. 다른 맥북에서 실험 불러오기로 재사용할 수 있습니다. 원문이 포함되므로 공유할 때 내용을 확인하세요.
- **결과 JSON**: 입력 원문은 제외하고 이름·정답·원문 SHA-256, 모델 이름·digest·알려진 실행기 버전, 설정, 문서 실행 순서, 모든 응답/실패, 준비 기록, 집계값을 담습니다.
- **지표 CSV**: 현재 화면의 비교 표를 저장합니다. 스프레드시트 수식으로 오인될 문자는 이스케이프합니다.
- 결과 파일은 자동 저장하지 않습니다. 내려받기 버튼을 누르면 내보낼 파일을 로컬 서버 메모리에 임시로 준비하며 링크는 10분 동안 사용할 수 있습니다. 디스크에는 사용자가 내려받는 파일만 남습니다. 자동 다운로드가 시작되지 않으면 화면 아래의 준비된 파일 링크를 누르세요. 각 파일의 생성 시점과 설정을 함께 보관하세요. 현재 결과 JSON을 화면에 다시 불러오는 기능은 없으며 실험 설정·데이터 JSON만 불러옵니다.
