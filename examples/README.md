# 바로 불러오는 가상 평가 데이터

이 폴더의 문서는 앱 체험을 위해 만든 **가상 예제**입니다. 실제 사용자 문서나 성능을 대표하는 벤치마크 데이터가 아닙니다. 세 파일 모두 문서·정답 배열이므로 **‘데이터 JSON 읽기’**로 불러옵니다. ‘실험 불러오기’에는 넣지 않습니다.

## Choice: 문의 부서 고르기

- 파일: [choice-support.json](choice-support.json)
- 유형: Choice
- 질문: `이 문의를 처리할 담당 부서를 선택하세요.`
- 선택지:

```text
billing = 결제, 청구, 환불
technical = 오류, 장애, 기능 문제
account = 계정, 로그인, 회원 정보
```

정답은 표시 문구가 아닌 `billing` 같은 **선택지 ID**입니다. 선택지 이름을 바꾸면 JSON의 정답도 맞춰 바꿔야 합니다.

## Score: 긴급도 점수

- 파일: [score-urgency.json](score-urgency.json)
- 유형: Score
- 질문: `이 문의는 얼마나 긴급한가요? 고객의 표현보다 실제 영향 범위를 기준으로 판단하세요.`
- 단계 설명:

```text
일반 · 일정에 맞춰 처리해도 됨
주의 · 일부 사용에 지장, 오늘 확인 필요
긴급 · 전체 서비스 중단 또는 즉시 큰 피해
```

위에서부터 0·1·2점입니다. 모델의 기대 점수는 소수일 수 있습니다. 소수 정답을 직접 넣으면 MAE·RMSE에는 포함되지만 정수 단계 분류 지표에는 포함되지 않습니다.

## Noul: 환불 요청 확인

- 파일: [noul-refund.json](noul-refund.json)
- 유형: Noul
- 명제: `이 문의는 이미 지불한 돈의 환불을 요청한다.`
- 선택지 의미:

```text
true = 이미 지불한 돈을 돌려 달라는 요청이다
false = 환불 요청이 아니다
```

정답은 JSON의 `true`·`false`입니다. 따옴표가 없는 불리언 값을 사용합니다.

## 내 데이터로 바꿀 때

```json
[
  {"name": "짧은 문서 이름", "text": "판단할 원문", "expected": null}
]
```

- `name`: 결과에서 알아보기 위한 이름입니다.
- `text`: 모델에게 보여 줄 문서입니다.
- `expected`: 사람이 확인한 정답입니다. 모르면 `null`을 사용합니다.

실제 문서로 바꾼 파일은 Git에 포함되는 이 폴더를 덮어쓰지 말고 `experiments/` 같은 제외 폴더에 저장하세요. 질문까지 바꾸었다면 예제의 기존 정답이 여전히 맞는지도 다시 확인합니다.
